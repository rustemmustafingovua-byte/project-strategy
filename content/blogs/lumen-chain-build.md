# Как я построил собственный блокчейн на TypeScript: от идеи до работающей сети Lumen Chain

## Почему TypeScript?

Когда я решил создать Lumen Chain, выбор языка программирования был очевиден. TypeScript даёт строгую типизацию, что критично для блокчейна: одна ошибка в логике консенсуса — и сеть теряет целостность. JavaScript-экосистема позволила быстро итерировать, а компилятор ловил 80% багов до запуска.

## Архитектура: минимализм как принцип

Lumen Chain — это не очередной EVM-клон. Мы начали с вопроса: что *необходимо* для децентрализованной сети?

- **Блок-структура**: заголовок, список транзакций, Merkle-корень. Всё.
- **Консенсус**: модифицированный Proof-of-Stake с адаптивным временем блока.
- **VM**: собственная байт-код машина для смарт-контрактов.
- **P2P**: libp2p для обнаружения пиров и gossip-протокола.

Каждый компонент писался с нуля. Никаких зависимостей, которые нельзя аудировать.

## Самая большая сложность: состояние

Блокчейн — это, по сути, машина состояний. Как хранить изменения, чтобы оставаться быстрым?

Я применил паттерн **Merkle-Patricia Trie** с оптимизацией под hot-path. Вместо полной перестройки дерева при каждом блоке мы используем инкрементальные обновления. Результат: 10 000+ TPS на обычном сервере.

## Сетевая часть:libp2p в деле

P2P-сеть — это 90% боли. Мы использовали:
- mDNS для локального обнаружения
- DHT для децентрализованного пиринга
- Протокол защиты от спуфинга через node ID, подписанный приватным ключом

## Результат

Lumen Chain запущен, открыт для разработчиков. API документация готова, SDK на TypeScript уже позволяет деплоить контракты за 5 минут.
